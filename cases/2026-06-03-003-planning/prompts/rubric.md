# 评分标准（裁判用）

按 5 维评分（每维 1-5 分），总分 25：

## 1. 顺序与依赖（0-5）
- 步骤之间依赖关系是否交代清楚？
- 是否识别了哪些可以并行、哪些必须串行？
- 顺序是否合理（不是"先做最难的后做最简单的"）？

## 2. 完成定义（DoD）（0-5）
- 每一步是否给出了"怎么算这步真的干完了"？
- DoD 是否可验证（不是"做得差不多了"）？
- 是否区分了"代码完成"和"产品完成"？

## 3. 模糊点的显式处理（0-5）
- 5 个模糊点（数据稀疏 / reviewer / 聚类粒度 / 敏感信息 / 历史数据）是否都点到了？
- 是否给了**明确假设**而不是"看情况"？
- 假设是否经得起推敲（不是把决策推给未来）？

## 4. 风险识别（0-5）
- 是否点出至少 2 个具体风险（不是"可能会出问题"这种空话）？
- 风险是否配了对策（至少是 mitigation 方向）？
- 是否考虑到了"模型本身的不确定性"风险？

## 5. 人机分工（0-5）
- 是否明确指出哪些决定**必须由人做**？
- 是不是把"我们 LLM 都能干"作为默认？
- 是否有具体的"人 review 的 checkpoint"位置？

## 评分锚点

- **5**: 维度全做到位，能直接拿去执行
- **3-4**: 主体到位，缺 1-2 个细节
- **1-2**: 框架有了，深度不够或漏维度
- **0**: 该维度缺失或答非所问
