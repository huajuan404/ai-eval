# 评分标准：网页体验品质

被评估产物是 `docs/article.html` —— 选手基于 `docs/source.md`（一篇关于 AI-native 工程团队的真实演讲文章）自由创作的单页网页。
评估时请**在浏览器中打开 HTML 文件**，以读者视角体验，再对照源文档逐维打分。
每维 0-5 分（0=完全失败，3=合格，5=出色），总分 25。

## 1. 第一印象与整体品质（0-5）

打开页面的那 2 秒钟——作为读者，你的第一反应是什么？

- 是「哇，这个排版认真做了」，还是「又一个博客模板」？
- 标题、副标题、首屏的视觉层次是否立刻建立了阅读意愿？
- 整体配色和字体选择是否传递出专业感和品质感？
- 如果这是你在技术大会上看到的展示页面，你会停下来看吗？

评分锚点：0=默认浏览器样式或极度粗糙；3=有明确设计意图，排版舒适；5=打开就觉得「这篇值得认真读」，品质感本身就是说服力

## 2. 信息可视化与论点传达力（0-5）

全文的灵魂是那张 Before/After 对比表，同时还有 3 个量化指标和 3 条团队原则。这些信息是否从「文字」变成了「视觉」？

- Before/After 对比是否有**图形化呈现**（图表、可视化组件、图形对比等），而不是仅靠 CSS 样式修饰的 HTML 表格？
- 3 个追踪指标是否利用了它们作为**量化数据**的特性（图表、进度条、动画计数等），而不是三段纯文字描述？
- 团队原则之间的逻辑关系是否有**视觉结构**（关系图、流程图、信息架构图等），而不是一个 bullet list？
- 读者能否不逐字阅读，仅通过扫一眼视觉元素就理解文章的核心论点？

关键判断标准：**如果去掉所有 CSS 样式，只看内容结构，这个页面和一篇 Markdown 有没有本质区别？** 如果没有——说明可视化不到位，信息仍然全靠文字传达。

评分锚点：0=全部内容都是文字段落 + CSS 排版，无任何可视化元素；3=有基础的图表或图形元素，但仅覆盖部分信息，实现方式常规；5=核心论点全部通过视觉图形传达，读者扫一眼就能理解结构，信息可视化本身就是叙事的一部分

## 3. 阅读体验（0-5）

从头到尾滚一遍，阅读过程是否流畅舒适？

- 滚动过程中是否有舒适的节奏感（重点自然浮现，而非信息过载）？
- 长段落是否有呼吸感（间距、分段、视觉断点）？
- 导航是否帮助而非干扰阅读？
- 手机上（375px 宽度）是否仍然可读、可用？
- 是否有任何让读者「卡住」或「分心」的地方？

评分锚点：0=阅读体验差，想关掉；3=能顺畅读完，没有明显障碍；5=从头到尾一口气读完，节奏恰到好处，想转发

## 4. 交互与动效品质（0-5）

页面中的交互和动效——如果有——是增强了还是干扰了阅读？

- 动效是否自然流畅（恰当的缓动曲线、合理的时长），还是生硬或过度？
- 交互是否服务于阅读目的（如引导视线、突出重点），还是为了炫技而存在？
- 状态切换（如暗色模式、折叠展开）是否平滑、不突兀？
- 交互是否有性能问题（滚动卡顿、动画掉帧）？

注意：一个没有任何动效但排版极其精美的静态页面，在这一维可以得到 3 分。只有当动效**确实增强了阅读体验**时才给高分。

评分锚点：0=动效粗糙或干扰阅读；3=动效不扣分，可能有微交互；5=动效精心编排，增强了叙事节奏和阅读沉浸感

## 5. 工程实现（0-5）

翻开代码——HTML/CSS/JS 的工程水准如何？

- HTML 是否语义化（`<header>`、`<nav>`、`<main>`、`<section>`、`<article>`、`<footer>`）？
- CSS 是否有体系（自定义属性/Design Token，而非散落硬编码）？
- JavaScript 是否干净（模块化、无泄漏、无冗余）？
- 代码是否体现出性能意识（避免强制重排、合理使用事件委托等）？

评分锚点：0=代码混乱、无结构；3=语义 HTML + CSS 变量 + JS 基本可读；5=整洁的模块化代码、完善的 CSS 架构、高性能的 DOM 操作、注释得当
