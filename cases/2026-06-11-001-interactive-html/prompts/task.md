# 任务：将一篇文章变成一个让人愿意读完的网页

## 素材

当前目录下的 `docs/source.md` 是一篇真实的技术博客文章——Fiona Fung 在 Code w/ Claude SF 2026 大会上的演讲 *"Running an AI-native engineering org"*。文章讲的是：当 AI agent 成了默认编码方式之后，一个一线工程团队如何重写了几乎所有流程。

## 为什么要做这个页面

这篇文章有很好的内容，但作为 Markdown 它只会被扫一眼就关掉。我们要把它变成一个**打开的瞬间就觉得值得认真看**的网页——那种你在技术大会上看到会停下来多看两眼的品质。

## 受众

一线技术团队的工程负责人。他们自己每天都在用 AI 工具，但不一定意识到：当编码速度不再是瓶颈之后，真正需要重写的不是代码，而是流程本身。他们见多了排版粗糙的技术博客，所以品质感本身就是说服力的一部分。

## 想要的感觉

- **打开的第一眼**：「这篇不是随便排版的博客，是认真做的。」
- **滚动阅读的过程**：节奏舒适，有呼吸感，重点自然浮现，不费力地一路读下去。
- **读到 Before/After 对比的地方**：不是被告知「旧的不如新的」，而是**一眼感受到**差距——那个瞬间就是全文的锚点，读者合上页面后唯一记得住的东西。
- **读完之后**：想转发给团队。

## 这个故事的核心

全文的灵魂是那张 Before/After 对比表——旧流程 vs 新流程的 4 个维度。这是论点，也是读者记忆的钩子。它不应该只是一张普通表格；它应该让读者一眼就**看到**变革的幅度。怎么做到，由你决定。

## 可视化要求

纯文字再怎么排版，读者仍然是在「读」。这篇文章里的信息有天然的结构和层次——流程对比、指标变化、原则清单。**读者应该能通过视觉图形一眼理解这些结构关系，而不需要逐字读完才知道。**

具体来说：

- **Before/After 对比**不应只靠文字排版来体现，而应该有真正的图形化呈现——让读者「看」到差距，而不是「读」完才知道有差距。
- **3 个追踪指标**（onboarding ramp time / PR cycle time / Claude-assisted commits）如果只是三段文字，就浪费了它们作为量化数据的说服力。
- **团队原则**（dogfood / keep flat / kill old processes）之间的逻辑关系，如果能用视觉结构（而非列表）表达，读者会更快记住。

用什么技术手段实现（SVG、Canvas、图表库、纯 CSS 图形、还是别的）完全由你决定。但如果整个页面从头到尾都是文字段落 + CSS 样式，那和一个好看的博客模板没有本质区别。

## 硬约束

- 输出到 `docs/article.html`，单文件（CSS 和 JS 全部内联；允许引用 CDN，但不得创建其他本地文件）
- 源文全部内容必须完整保留——文字、表格数据、链接，不得丢失、改写或总结
- 在桌面和手机上都能正常阅读

除此之外，用什么技术、什么设计风格、什么交互方式、什么动效节奏，全部由你决定。你唯一的目标是：**让读者打开这个页面，就想把它读完——并且读完之后，记得住。**
