# 2026-06-11-001-interactive-html

**测什么**：模型的 design sense + HTML 全栈工程能力。不绑 skill、不给技术规格——用创意简报（受众 / 感觉 / 叙事目的 / 品质锚点）激发模型的上限，让模型自己决定用什么手段达成目标。

## 与 md2html-skill case 的互补关系

| | md2html-skill | interactive-html |
|---|---|---|
| 约束方式 | skill 模板 + 技术规格书（13 条指令） | 创意简报（目的 / 感觉 / 受众 / 期望） |
| 测什么 | 指令遵循度 | design sense + 工程能力 |
| 天花板 | 被模板锁死，强模型间无区分度 | 开放式，上限由模型自身能力决定 |

## 设计要点

- **源文档**：Fiona Fung *"Running an AI-native engineering org"*（Claude Code 博客，83 行），自带 Before/After 对比表（叙事核心）、3 个关键指标、6 个清晰章节。
- **创意简报风格**：prompt 只描述「想要的感觉」和「受众是谁」，不指定具体技术实现（不提 Chart.js、IntersectionObserver 等）。模型自己决定用什么手段让读者「打开就想读完」。
- **品质锚点**：用「科技杂志」「大会议展示」等隐喻把模型的生成分布往高品质拉，避免走训练数据的平均路径。
- **硬约束极少**：单文件、内容保真、响应式。其余全部交给模型发挥。

## 判分

- **check.sh**（确定性，8 条）：产物存在 + 有效 HTML5 + viewport meta + 4 个关键标识保真 + 单文件约束。
- **LLM 裁判 5 维 × 5 分**：第一印象 / 核心论点传达力 / 阅读体验 / 交互与动效品质 / 工程实现；≥15 良好。
- **人工终审**：浏览器打开 `output/<runner>/docs/article.html` 并排比对——「打开就想读完」这个标准最终只能人眼判断。
